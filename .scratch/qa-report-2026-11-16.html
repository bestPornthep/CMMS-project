Findings and status

Major - fixed in source

Protected APIs were called before authentication

Observed: The login page requested users, assets, PM tasks, and templates before a session existed. These requests returned 401 and logged PM data load failed HttpErrorResponse.

Fix: PM preload is now gated on an authenticated session, and the AuthService no longer preloads the user list before authentication.

Retest: Corrected local dev login page loaded without unauthenticated API errors. Production still showed the old behavior because its deployed bundle had not been updated.

Files: frontend/src/app/app.config.ts and frontend/src/app/core/services/auth.service.ts.

Unconfirmed / needs follow-up

Intermittent session or navigation bounce

One direct load of Master Plan redirected to login even though the user appeared signed in. Five later direct loads and a reload passed. The lifecycle test also experienced navigation to unrelated PM pages and could not proceed reliably.

Recommendation: repeat the full lifecycle with a clean browser session after the corrected bundle is deployed, while capturing timing and network traces.

Minor / performance

Slow initial rendering on large PM pages

Assign PM and Calendar initially appeared blank at approximately 3.5 seconds and rendered at approximately 6 seconds. Assign PM also produced a large page body.

Data quality / product review

Dashboard metrics look inconsistent or static

PM Compliance displayed 0% alongside positive trend text such as +2.4%. Other cards showed fixed-looking text such as +12% vs last month and Optimal load. Workload totals were much larger than the total work-order card.

These may be intentional mock/demo metrics, but they should be verified against the product requirement and backend data.

Data hygiene

Test records and mock controls are visible

Dashboard activity and overdue lists contained E2E/test records, and Mock Preview Data buttons were visible on production pages. Confirm whether these are intended for the current environment and remove or hide them before release if not.

Minor UX

Other route and login UX observations

  • Unknown routes redirect to dashboard or login instead of a dedicated not-found page.
  • Some protected-route redirects show the original URL briefly before Unauthorized.
  • The login form remains reachable when already authenticated.

POST /products — Allow Engineers + Assign Creator Ownership

Confirmed live on http://10.144.15.76:3000 2026-08-29: an Engineer creating a brand-new Product inline from the Create PM page gets 403 Forbidden. Frontend fix decision: Engineers should be allowed to create products (confirmed by product owner).

1. Repro (confirmed against live server)

Logged in as ENG-TST-3 (Engineer), called:

POST /api/v1/products
{ "id": "ZZTEST-DIAG-01", "name": "ZZTEST-DIAG-01" }

Response:

403 Forbidden
{ "message": "Only admin or manager can create products", "error": "Forbidden", "statusCode": 403 }

Frontend caller: frontend/src/app/pages/pm-create/pm-create.component.ts auto-creates a Product when the user types a Product ID that doesn't exist yet, gated only by the pm.create.submit permission — which Engineers already have. The 403 from the backend is swallowed into a generic "Failed to create new product. Please try again." toast, which is misleading since retrying never succeeds for an Engineer under the current backend rule.

2. Required Change

#WhatDetail
1Relax role check POST /api/v1/productsAllow admin, manager, and engineer (matching the frontend's existing pm.create.submit gate). Technicians still not allowed — they never have pm.create.submit.
2Assign creator ownership row on createAlready a known gap (see backend.instructions.md) — when a product is created, insert an ownership row so the creating Engineer's ownedProducts includes the new product immediately. Without this, the Engineer can create the product but still can't use it (no access to it afterward).
Why ownership assignment matters here specifically: the frontend's createProduct() flow (pm.service.ts) calls authService.init() right after a successful create, to refresh the user's profile so the new product shows up in their accessible/owned list. If ownership isn't assigned server-side, the refresh is a no-op and the very next step in the same Create PM flow (creating the Asset under that product) will likely fail permission checks too.

3. Notes

  • No schema change expected — this is a permission-check + ownership-row-insert fix only, assuming the ownership table/relation already exists (used elsewhere for existing seeded engineer/product ownership).
  • Manager/Admin behavior is unchanged.
  • Frontend needs no change once this ships — it already only requires pm.create.submit, which Engineers have.

1. How to Access the API

The frontend talks to the backend via frontend/src/environments/environment.ts's apiUrl. All routes are mounted under the /api/v1 prefix.

EnvironmentapiUrlNotes
Shared dev serverhttp://10.144.15.76:3000Docker container cmms-backend. Default value committed in environment.ts.
Local backendhttp://localhost:<PORT>Run cd backend; npm run start:dev (default port 3000 from backend/.env). If port 3000 is already taken locally (e.g. by the shared Docker container), start with an override: $env:PORT='3001'; npm run start:dev.
⚠️ Don't commit environment.ts pointed at localhost. If you change apiUrl to test against a local backend, revert it to http://10.144.15.76:3000 before committing/merging.

All request/response bodies are JSON. CORS is open (origin: '*') so any frontend origin can call the API during development.

2. Authentication Flow

The API uses JWT bearer tokens. Every route except POST /auth/login and POST /auth/refresh requires a token.

Step 1 — Login

POST /api/v1/auth/login
Content-Type: application/json

{ "employeeId": "ENG-TST-1", "password": "eng123" }

Response:

{
  "token": "eyJhbGciOi...",       // JWT — use this in Authorization header
  "refreshToken": "RT-xxxxxxxx",
  "user": {
    "employeeId": "ENG-TST-1",
    "name": "...",
    "initials": "...",
    "baseRole": "engineer",       // technician | engineer | manager | admin
    "roleLabel": "...",
    "department": "...",
    "ownedProducts": ["CUST-001", "CUST-002"],
    "delegatedProducts": [ /* active delegations granted to this user */ ],
    "permissions": [ /* ... */ ]
  }
}

Note: the field is token, not accessToken — some older docs in this repo say accessToken, that's stale.

Step 2 — Store & attach the token

The existing AuthService already does this for you (see frontend/src/app/core/services/auth.service.ts):

localStorage.setItem('assetintel_auth', res.token);

The authInterceptor (frontend/src/app/core/interceptors/auth.interceptor.ts) automatically reads this key and attaches it to every outgoing request:

Authorization: Bearer <token>

You don't need to attach the header manually when calling through HttpClient — it's global.

Step 3 — Refresh & logout

EndpointPurpose
POST /api/v1/auth/refresh — body { "refreshToken": "..." }Returns a new token/refreshToken pair. No auth header required.
POST /api/v1/auth/logoutInvalidates the server-side refresh token for the current user. Returns 204. Requires auth header.
GET /api/v1/auth/meReturns the decoded JWT claims for the current session (same shape as the user object above, minus delegatedProducts/permissions re-lookup).

3. Quick Start with ApiService

Don't call HttpClient directly — use the existing ApiService (frontend/src/app/core/services/api.service.ts), which already has typed methods for every endpoint below.

import { inject } from '@angular/core';
import { ApiService } from './core/services/api.service';

const api = inject(ApiService);

// Get PM tasks for a department, excluding completed ones
const tasks = await api.getTasks(undefined, 'Test', undefined, undefined, 'Done');

// Create a task
const created = await api.createTask({
  title: 'Monthly Inspection',
  description: '...',
  frequency: 'Monthly',
  assetId: 'THC-P1-01',
  nextDueDate: new Date(),
  estimatedHours: 1.5,
  status: 'Pending',
});

If you need a new endpoint that isn't on ApiService yet, add a typed method there rather than calling HttpClient inline in a component — keeps the API contract in one place.

4. Error Handling & Roles

Roles: technician < engineer < manager < admin. Most write endpoints are gated by baseRole checks in the controller (not just route-level guards), so the same endpoint can return different results depending on who's calling it.

StatusMeaningCommon cause
401UnauthenticatedMissing/expired/invalid JWT.
403ForbiddenRole or ownership check failed inside the controller (e.g. technician calling GET /delegations, engineer creating a template for another department, technician viewing a task not assigned to them).
404Not foundID doesn't exist, or a technician has no access to the record's product (some 404s are used deliberately instead of 403 to avoid leaking existence).
409ConflictDuplicate ID on create (e.g. product/asset ID already exists).
400Bad requestValidation failure (class-validator DTOs on POST/login).

NestJS error responses follow the standard shape: { "statusCode": 403, "message": "...", "error": "Forbidden" }.

5. Endpoint Reference

🔑 Auth /api/v1/auth

EndpointAuthDescription
POST /auth/loginPublicBody: { employeeId, password }. Returns { token, refreshToken, user }.
POST /auth/refreshPublicBody: { refreshToken }. Returns a fresh token pair.
GET /auth/meJWTCurrent user's decoded claims.
POST /auth/logoutJWTInvalidates the refresh token. 204 on success.

👤 Users /api/v1/users

EndpointAuthDescription
GET /users?role=&department=JWTList users, optional filters.
GET /users/:idJWT404 if not found.
PATCH /users/:idJWT, admin-onlyUpdate department/role/etc. 403 for non-admins.

📦 Products /api/v1/products

EndpointAuthDescription
GET /productsJWTList all products.
POST /productsJWT, admin/manager-onlyBody: { id, name }. 409 on duplicate ID, 403 for other roles.

⚙️ Assets /api/v1/assets

EndpointAuthDescription
GET /assets?location=&department=JWTList assets, optional filters. location = productId/site code.
POST /assetsJWT, technician forbiddenBody: { id, name, location, department }.

📋 PM Tasks /api/v1/pm-tasks

EndpointAuthDescription
GET /pm-tasks?status=&excludeStatus=&department=&productId=&assignedTo=JWT, scopedTechnicians only see tasks assigned to them or on delegated products.
GET /pm-tasks/:idJWT, scoped403 if the task isn't assigned to a requesting technician / product not owned.
POST /pm-tasksJWT, technician forbidden (unless delegated)Create a single PM task. See payload below.
PUT /pm-tasks/:idJWT, scoped by role/delegationUpdate a task (assign, record execution, approve/reject).
DELETE /pm-tasks/:idJWT, admin/manager-only403 for other roles.
POST /pm-tasks/scheduleJWTCreate a recurring PM schedule (generates future task instances). See payload below.
PUT /pm-tasks/schedule/:seriesIdJWTUpdate an existing schedule series.
